B
Tracking · what the site sends to Meta

The site sends Meta purchase data that can't be fully trusted yet.

How one order reaches Meta

1 orderplaced on pomad.paris
Browser copySent by the Simprosys app's pixel on the thank-you page. Its ID is the Shopify order's ID.Seen in the site code
Server copySent server-to-server (Meta's "Conversions API"). Two tools on the site could send it: Simprosys or Addingwell.Sender and ID not visible from outside
Same ID on bothMeta merges them: 1 order = 1 purchase.
Different or missing IDMeta keeps both: 1 order can show as 2 purchases.

This merging is called deduplication. Over 28 days, Meta received 6,325 browser and 3,984 server Purchase events. The server count is 63% of the browser count, which tells us the two copies don't always arrive together. It doesn't tell us whether Meta merges them.

How to check B1, step by step

  1. See who sends the server copy. Events Manager → PIXELS POMAD → Settings. Under "Conversions API" the connected partner is named (Simprosys, Addingwell or another).
  2. See whether Meta merges them. Events Manager → Overview → click Purchase. The detail view shows events received from "Browser" and "Server" and how many were deduplicated. The Diagnostics tab flags server events that can't be merged.
  3. Follow one real order. Open Events Manager → Test events, place one test order on the site and note its order number. The browser Purchase appears with its event ID. The server copy should arrive with the same ID and be marked "Deduplicated".
  4. Compare with Shopify for one week. Shopify orders per day next to Meta's browser and server Purchase events per day. If browser events ≈ orders, the browser side is clean. Whatever the server side adds without merging is double counting.

Steps 1–3 need access to the pixel in Events Manager, which is being granted. Step 4 needs Shopify's daily order count.

Technical detail for the developer

The browser Meta pixel is loaded by the Simprosys (Google Shopping Feed) app's web pixel (storage.googleapis.com/gsf-scripts/custom-pixels/pomadparis.js), not by Meta's Shopify app. It also posts each purchase, with the event ID, to conversions-gsf.simpshopifyapps.com. Addingwell runs as a Shopify custom pixel that loads GTM-PQKW2PKK from tagging.pomad.paris and pushes the order to a server container.

C
Campaign setup · how the account is organised

Settings reward views, and budget is spread thin.

C1
All three live campaigns count view-through and video-view purchases, and optimise on them.Setting: 7-day click + 1-day view + 1-day engaged view. Meta learns to find people likely to buy after only seeing an ad.
3 of 3live campaigns count views
C2
Retention takes 17.5% of spend and reaches far beyond customers.It's set up for the customer list (38,000–44,700 people), but Advantage+ audience is on and lets Meta go wider. 730,100 people reached in 30 days. ROAS shown 4.91, ROAS 7-day click 2.27, and 55% of its purchases are view-through.
730kpeople reached vs ~41k on the list
C3
The website buyer audiences don't show a size."Purchase 30j", "180j" and "730J" are built from the pixel. Ads Manager shows "size unavailable" for them, so it can't be confirmed that they fill. Retention excludes "Purchase 30j", so it can't be confirmed that last month's buyers are left out. The Klaviyo customer lists ("Purchase All Time", 38,000–44,700, and "Purchase 90J", 12,600–14,800) show their size, refresh daily, and are what prospecting excludes. That exclusion works.
Size unavailablewebsite buyer audiences
C4
€3,000 a day is shared by 93 ad sets.About €32 each on average. 16 have minimum spends (€740 a day locked in). 166 of 357 ads got under €50 in 30 days. Meta says an ad set learns best with about 50 purchases a week.
93ad sets, ~€32 a day each
C5
The Testing campaign does most of the scaling.It carries 55% of spend, and 67% of that goes to ads older than 30 days. No scaling campaign is live (Cost Cap paused 19 Oct, ASC 14 Oct). Spend is €4.2k a day vs €15.1k in February.
€4.2ka day now vs €15.1k in Feb
What it means

The setup rewards ads that are seen, mixes testing with scaling, and gives most new ads too little budget to judge.

What the data shows

Of the pages tried so far, the homepage performs best, on Meta's default count and on 7-day click.

Not tried yet
